# HSE Guard — Database Migration Plan: SQLite to PostgreSQL

This document outlines the detailed, zero-downtime, safe migration strategy for transitioning HSE Guard from local SQLite development storage to production-grade PostgreSQL 15+.

---

## 1. Schema Compatibility & Static Review

HSE Guard uses Django 5.2 ORM constructs designed for relational portability. A static audit of the models across all 19 installed applications confirms complete PostgreSQL readiness:

| Category | SQLite Implementation | PostgreSQL Compatibility | Audit Result |
| :--- | :--- | :--- | :--- |
| **Primary Keys** | `BigAutoField` (INTEGER PRIMARY KEY) | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 100% Native |
| **JSON Fields** | SQLite `JSON` text functions | `JSONB` native binary storage with GIN indexing capability | High Performance Gain |
| **Date & Time** | ISO 8601 text strings | `TIMESTAMP WITH TIME ZONE` (`TIMESTAMPTZ`) | `USE_TZ=True`, Tehran offset handled cleanly |
| **Enumerations** | `models.TextChoices` / `CharField` | `VARCHAR(N)` with Django-level validation | Fully Supported |
| **Foreign Keys** | SQLite pragmas (`PRAGMA foreign_keys = ON`) | Strict relational constraints with `CASCADE`, `PROTECT`, `SET_NULL` | Fully Supported |
| **Uniqueness & Indexes** | Composite `UniqueConstraint` and `Index` | PostgreSQL b-tree composite indexes | Fully Supported |

## 2. Concurrency, Locking, and Transaction Atomicity

In multi-user enterprise operations, high-risk workflows utilize database transactions:
- **`@transaction.atomic` Decorator:** Applied across:
  - `Permit` status transitions and SIMOPS conflict overrides.
  - `LiftingPlan` multi-gate approval and sign-offs.
  - `PSSRReview` checklists and critical gate verifications.
  - `Document` revision creation and version archiving.
  - `MaintenanceWorkOrder` completion and asset condition adjustments.
- **Row-Level Locking (`select_for_update`):**
  - In SQLite, table-level locking is used.
  - In PostgreSQL, row-level locking (`SELECT ... FOR UPDATE`) executes natively without blocking unrelated rows in the same table, drastically improving concurrent throughput.

## 3. Migration Procedure: SQLite to PostgreSQL

### 3.1 Pre-Migration Prerequisites
1. Ensure both PostgreSQL and Python `psycopg2-binary` or `psycopg` are installed on the host:
   ```bash
   pip install psycopg2-binary
   ```
2. Verify that all forward migrations are clean and applied on SQLite:
   ```bash
   python backend/manage.py migrate
   python backend/manage.py makemigrations --check
   ```
3. Create target database in PostgreSQL:
   ```sql
   CREATE DATABASE hse_guard_staging OWNER hse_guard_staging ENCODING 'UTF8';
   ```

### 3.2 Step 1: Dump Data from SQLite
Export data using Django `dumpdata`, explicitly excluding content types and system permissions to prevent primary key collision upon loading:
```bash
cd backend
python manage.py dumpdata \
    --natural-foreign \
    --natural-primary \
    --exclude contenttypes \
    --exclude auth.permission \
    --indent 2 \
    --output sqlite_data_dump.json
```

Verify dump integrity:
- Check file size: `ls -lh sqlite_data_dump.json`
- Verify UTF-8 encoding: ensure Persian text characters are intact.

### 3.3 Step 2: Initialize PostgreSQL Schema
Temporarily configure environment variables to point to PostgreSQL:
```bash
export DB_ENGINE=postgresql
export DB_NAME=hse_guard_staging
export DB_USER=hse_guard_staging
export DB_PASSWORD=your_secure_password
export DB_HOST=127.0.0.1
export DB_PORT=5432
```

Run schema creation via standard Django migrations:
```bash
python manage.py migrate --run-syncdb
```

### 3.4 Step 3: Load Data into PostgreSQL
Load the serialized JSON data into PostgreSQL:
```bash
python manage.py loaddata sqlite_data_dump.json
```

### 3.5 Step 4: Reset Primary Key Sequences in PostgreSQL
Because PostgreSQL uses identity sequences, synchronize sequence counters to prevent unique key violation on future inserts:
```bash
python manage.py sqlsequencereset accounts organizations workplaces risks checklists inspections findings capa auditlog notifications dashboard reports knowledge_base ai_assistant incidents permits assets workforce environment scaffolds documents calculators lifting pssr surveys chat fleet_energy | python manage.py dbshell
```

## 5. Rollback Procedure

If data corruption, connection failure, or sequence desynchronization occurs:
1. Revert `.env` to SQLite:
   ```ini
   DB_ENGINE=sqlite3
   DATABASE_PATH=db.sqlite3
   ```
2. Restart backend service:
   ```bash
   sudo systemctl restart hse-guard-backend
   ```
3. Drop and recreate PostgreSQL staging database to clean up partially loaded tables:
   ```sql
   DROP DATABASE hse_guard_staging;
   CREATE DATABASE hse_guard_staging OWNER hse_guard_staging ENCODING 'UTF8';
   ```
4. Investigate error logs in `/opt/hse-guard/logs/backend.log`.
