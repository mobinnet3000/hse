# AGENT.md — دستورالعمل اجرای عامل هوش مصنوعی

## ۱. ترتیب مطالعه
1. این فایل را بخوان.
2. برای شناخت محصول، فقط بخش‌های مرتبط `PROJECT.md` را بررسی کن.
3. برای معماری، مدل داده، API، امنیت و اجرا، به بخش مرتبط `TECHNICAL.md` مراجعه کن.
4. اگر اطلاعات کافی است، از بازخوانی کامل مستندات خودداری کن.

## ۲. اصول غیرقابل‌مذاکره
- قبل از هر تغییری، ساختار مخزن، فایل‌های موجود، وابستگی‌ها و وضعیت Git را بررسی کن.
- کد موجود را حفظ کن؛ بازنویسی گسترده، حذف فایل یا تغییر معماری بدون ضرورت و تأیید انجام نده.
- فقط فایل‌های لازم را ایجاد یا اصلاح کن.
- الزامات `PROJECT.md` و `TECHNICAL.md` بر حدس و سلیقه شخصی مقدم‌اند.
- رابط کاربری فارسی و RTL باشد.
- جداسازی اطلاعات سازمان‌ها باید در تمام endpointهای مرتبط اعمال شود.
- مجوزها و محاسبات حساس باید در سمت سرور اعتبارسنجی شوند.
- خروجی AI صرفاً پیشنهاد است و نیاز به تأیید انسان دارد؛ سامانه بدون AI نیز باید کار کند.
- از جعل قوانین، استانداردها، منابع، نتایج آزمون یا قابلیت‌های پیاده‌سازی‌شده خودداری کن.
- استفاده از Docker، Docker Compose و Dockerfile ممنوع است.

## ۳. گردش کار هر وظیفه
1. **بررسی:** فایل‌ها و وابستگی‌های مرتبط را پیدا کن؛ تغییرات موجود کاربر را حفظ کن.
2. **برنامه‌ریزی:** راهکار کوچک و مشخص انتخاب کن؛ فقط در ابهام مؤثر سؤال بپرس.
3. **اجرا:** تغییرات را مرحله‌ای و با حداقل دست‌کاری انجام بده.
4. **اعتبارسنجی:** آزمون‌های مرتبط را اجرا کن؛ در صورت امکان مسیرهای موفق، خطاها، مجوزها و جداسازی سازمانی را بررسی کن.
5. **بازبینی:** خطاهای احتمالی، تغییرات ناخواسته و سازگاری با مستندات را بررسی کن.
6. **گزارش:** نتیجه واقعی، فایل‌های تغییرکرده، آزمون‌های اجراشده و مشکلات باقی‌مانده را خلاصه کن.

## ۴. کیفیت و امنیت
- اعتبارسنجی ورودی، مدیریت خطا، مجوز دسترسی و ثبت رویدادهای ضروری را رعایت کن.
- اطلاعات محرمانه و کلیدهای API را در frontend، مخزن Git یا log قرار نده.
- برای تغییرات پایگاه داده، migration سازگار و قابل اجرا بساز.
- در صورت تغییر API، سازگاری frontend و backend را بررسی کن.
- برای عملیات حساس، رفتارهای مرزی و دسترسی غیرمجاز را آزمایش کن.
- از داده واقعی یا حساس در fixture، تست و نمونه‌های نمایشی استفاده نکن.
- قابلیت ناقص را کامل‌شده معرفی نکن؛ محدودیت‌ها را صریح گزارش بده.

## ۵. صرفه‌جویی در توکن
- فقط فایل‌ها، بخش‌ها و خروجی‌های مرتبط را بخوان.
- به‌جای چاپ کامل فایل‌ها یا logهای طولانی، از جست‌وجو، فیلتر و خروجی خلاصه استفاده کن.
- از تکرار مستندات، برنامه‌ریزی طولانی و توضیح بدیهیات خودداری کن.
- وضعیت کار را در چند خط نگه دار: هدف، تغییرات، آزمون‌ها و کار باقی‌مانده.
- قبل از اجرای مجدد فرمان، نتیجه اجرای قبلی را بررسی کن.
- اگر وظیفه محدود است، مستقیم اجرا کن؛ برای تغییر گسترده ابتدا برنامه کوتاه ارائه بده.

## ۶. گزارش نهایی
در پایان هر وظیفه، کوتاه و دقیق اعلام کن:
- **انجام شد:** تغییرات اصلی.
- **فایل‌ها:** فایل‌های ایجاد یا اصلاح‌شده.
- **آزمون‌ها:** فرمان‌های اجراشده و نتیجه واقعی.
- **باقی‌مانده:** خطاها، محدودیت‌ها یا اقدام ضروری بعدی.

هیچ آزمونی را که اجرا نشده، موفق اعلام نکن و هیچ تغییری را که انجام نشده، انجام‌شده گزارش نده.
