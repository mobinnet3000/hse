# سامانه مدیریت ایمنی، بهداشت و محیط زیست (HSE Guard)
## راهنمای گام‌به‌گام ارزیابی و دمو فاز ۰۸: مدیریت پروانه‌های کار (PTW) و تحویل شیفت

این راهنما برای کاربران غیرفنی، مدیران پروژه و کارشناسان HSE نوشته شده است. با دنبال‌کردن گام‌ها می‌توانید همه قابلیت‌های فاز ۰۸ را بدون دانش برنامه‌نویسی ارزیابی کنید.

> **هشدار مهم:** دستور بذرپاشی دمو (`seed_demo_data`) برای پایگاه داده اختصاصی دمو طراحی شده است. پیش از اجرا از پایگاه داده واقعی نسخه پشتیبان بگیرید. این دستور دیگر رمز حساب‌های موجود را به‌طور خودکار تغییر نمی‌دهد و اگر کد سازمان دمو از قبل توسط سازمانی غیردمو اشغال شده باشد، متوقف می‌شود.

### ۱. حساب‌های کاربری آزمایشی

رمز عبور همه حساب‌های دمو در **اولین ایجاد** برابر `Pass-12345-abc` است. اجرای دوباره بذرپاشی این رمز را بازنویسی نمی‌کند؛ مگر اینکه آگاهانه پرچم `--reset-demo-passwords` را بدهید.

| نام کاربری | نام نمایشی | نقش در فولاد البرز | نقش در پتروشیمی سپهر | کارهای اصلی |
| :--- | :--- | :--- | :--- | :--- |
| `demo_admin` | مدیر سامانه | مدیر کل پلتفرم | مدیر کل پلتفرم | دسترسی فراسازمانی، مناسب برای بررسی کلی |
| `demo_hse_manager` | رضا حسینی | مدیر HSE | مدیر HSE | بررسی، تأیید، رد، فعال‌سازی و مختومه‌سازی |
| `demo_inspector` | محمد کاظمی | بازرس HSE | — | کنترل میدانی، تحویل‌گیری شیفت |
| `demo_supervisor` | علی رستمی | سرپرست کارگاه | — | درخواست مجوز، تعلیق/ازسرگیری، ثبت تحویل شیفت |
| `demo_petro_supervisor` | سعید کریمی | — | سرپرست کارگاه | درخواست مجوز و تحویل شیفت در پتروشیمی |
| `demo_viewer` | سارا تهرانی | — | حسابرس خواندنی | مشاهده گزارش‌ها بدون امکان تغییر |

> داده‌های دمو با `is_synthetic=True` علامت‌گذاری شده‌اند و با پرونده‌های واقعی کارگاه تداخل ندارند.

### ۲. راه‌اندازی سریع (لینوکس / macOS)

در ریشه پروژه `/home/mob/Documents/hse`:

```bash
# ترمینال اول — بک‌اند
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo_data
python manage.py runserver 127.0.0.1:8000
```

```bash
# ترمینال دوم — فرانت‌اند
cd frontend
npm install
npm run dev
```

سپس مرورگر را روی `http://localhost:5173` باز کنید. خروجی موفق بذرپاشی شامل این خط است:

```text
All synthetic demo data seeded successfully with is_synthetic=True.
```

اگر می‌خواهید داده‌ها را در یک پایگاه داده جداگانه و بدون دست‌زدن به فایل اصلی آزمایش کنید:

```bash
cd backend
DATABASE_PATH=/tmp/hse-phase08-demo.sqlite3 python manage.py migrate
DATABASE_PATH=/tmp/hse-phase08-demo.sqlite3 python manage.py seed_demo_data
DATABASE_PATH=/tmp/hse-phase08-demo.sqlite3 python manage.py runserver 127.0.0.1:8000
```

### ۳. سناریوهای آزمایشی

#### سناریوی ۱: ورود و مشاهده فهرست مجوزها
1. با `demo_supervisor` و رمز `Pass-12345-abc` وارد شوید.
2. از منوی کناری، **«مجوزهای کار و تحویل شیفت»** را باز کنید.
3. کارت‌های شاخص (کل، فعال، در انتظار بررسی/تأیید، معلق/منقضی) و جدول مجوزها را ببینید.
4. فیلتر «کار در ارتفاع» را انتخاب کنید؛ فقط مجوز مربوط به جرثقیل ریخته‌گری نمایش داده می‌شود. سپس فیلتر را به «همه انواع مجوز» برگردانید.
5. روی «مشاهده و اقدامات» مجوز `PTW-202610-0101` کلیک کنید. چون این مجوز فعال است، دکمه‌های تعلیق، اتمام کار و مختومه‌سازی (بر اساس نقش شما) دیده می‌شوند.

#### سناریوی ۲: ثبت درخواست و اجرای تفکیک وظایف (SoD)
1. روی **«+ درخواست مجوز جدید»** کلیک کنید.
2. فرم را پر کنید:
   - کارگاه: **خط نورد گرم**
   - نوع فعالیت: **کار گرم و شعله**
   - عنوان: **تعمیر و جوشکاری حفاظ کوره پیشگرم**
   - شرح فعالیت: **برش بخش فرسوده و جوشکاری نبشی‌های تقویت‌کننده**
   - محل دقیق: **جنب مشعل شماره ۴**
   - نفرات اجرایی: **حسن اکبری و رضا مرادی**
   - تجهیزات حفاظت فردی: **ماسک بخارات فلزی، دستکش چرمی ساق‌بلند**
   - تیک **«نیاز به ایزولاسیون مکانیکی/برقی (LOTO) دارد»** را بزنید.
3. **«ثبت و ارسال درخواست»** را بزنید. مجوز با کد یکتا در وضعیت «درخواست‌شده» ساخته می‌شود.
4. پرونده همان مجوز را باز کنید. چون شما درخواست‌دهنده هستید، دکمه «تأیید مجوز» **نمایش داده نمی‌شود**. این هم در رابط کاربری و هم در سرور اعمال می‌شود؛ حتی اگر درخواست `POST /permits/<id>/approve/` مستقیماً فرستاده شود، سرور آن را رد می‌کند.

#### سناریوی ۳: بررسی، تأیید و فعال‌سازی با کنترل‌های میدانی
1. خارج شوید و با `demo_hse_manager` وارد شوید.
2. مجوز درخواستی را باز کنید و **«📝 بررسی اولیه»** را بزنید و یادداشت بنویسید: «شروط ایمنی حریق و حضور دیده‌بان تأیید شد».
3. سپس **«✓ تأیید مجوز (SoD)»** را بزنید. وضعیت به «تأییدشده» تغییر می‌کند.
4. **«⚡ فعال‌سازی و تأیید کنترل‌های میدانی»** را بزنید. چون LOTO الزامی است، فیلد جزئیات قفل‌گذاری اجباری است. بنویسید: «کلید سکسیونر برق کوره قطع، قفل زرد شماره ۴۵ و برچسب هشدار نصب شد.» و تأیید کنید.
5. وضعیت به «فعال و در حال اجرا» تبدیل می‌شود و نام و زمان تأییدکننده کنترل‌ها ثبت می‌شود.

#### سناریوی ۴: تعلیق، ازسرگیری، اتمام و مختومه‌سازی
1. در پرونده مجوز فعال، **«⏸ تعلیق موقت کار»** را بزنید و دلیل را وارد کنید: «نقص سیستم تهویه موضعی و انباشت دود».
2. پس از رفع نقص، **«▶ ازسرگیری مجدد کار»** را بزنید.
3. در پایان کار، **«🏁 اتمام کار عملیاتی»** را بزنید.
4. با **«🔒 مختومه‌سازی نهایی»** و ثبت خلاصه ترخیص، پرونده را ببندید: «محوطه پاکسازی شد، دیده‌بانی ۲ ساعته حریق انجام گرفت و قفل‌های برق باز شدند».

#### سناریوی ۵: تحویل شیفت و پذیرش توسط سرپرست ورودی
1. با `demo_supervisor` وارد شوید و تب **«🔄 تحویل و تحول شیفت»** را باز کنید.
2. بنر خلاصه ایمنی، تعداد مجوزهای فعال/معلق، خطرات حل‌نشده، اقدامات اصلاحی باز و حوادث ۷ روز گذشته را نشان می‌دهد.
3. **«+ ثبت تحویل شیفت جدید»** را بزنید:
   - کارگاه: **خط نورد گرم**
   - شیفت: **شیفت عصر**
   - تاریخ: امروز
   - **سرپرست تحویل‌گیرنده:** `demo_inspector — محمد کاظمی` را انتخاب کنید. (تعیین شخص اختیاری است؛ اگر تعیین شود، فقط همان شخص می‌تواند گزارش را تأیید کند.)
   - شرح رخدادها: «تولید خط نورد با ۸۰ تن بر ساعت پایدار بود. یک مورد جوشکاری نقاله انجام شد.»
   - خطرات فوری: «کف سالن در دهانه شماره ۲ مرطوب است.»
   - مجوز فعال متصل را تیک بزنید.
4. **«ثبت گزارش شیفت»** را بزنید. گزارش در وضعیت «در انتظار تحویل و تأیید» ثبت می‌شود.
5. خارج شوید و با `demo_hse_manager` وارد شوید. در تب تحویل شیفت، این گزارش را ببینید: دکمه تأیید **نمایش داده نمی‌شود** و پیام «در انتظار تأیید محمد کاظمی» دیده می‌شود. این کنترل سمت سرور هم دارد.
6. خارج شوید و با `demo_inspector` وارد شوید. حالا دکمه سبز **«✓ تأیید و تحویل‌گیری این شیفت»** را می‌بینید. آن را بزنید و یادداشت بنویسید: «شیفت تحویل گرفته شد و خطرات به اپراتورها ابلاغ گردید.»
7. وضعیت به «تأیید و تحویل‌گرفته‌شده» تغییر می‌کند و نام و زمان تحویل‌گیرنده ثبت می‌شود.

#### سناریوی ۶: مجوز منقضی و رفتار «فعال نبودن»
1. با `demo_supervisor` یک مجوز جدید بسازید و **هم زمان شروع و هم زمان پایان** را در گذشته وارد کنید (مثلاً دیروز).
2. پس از ثبت، وضعیت مؤثر آن در فهرست **«منقضی‌شده»** نمایش داده می‌شود.
3. فیلتر وضعیت را روی «فعال و در حال اجرا» بگذارید؛ این مجوز در فهرست فعال ظاهر نمی‌شود. کارت «معلق یا منقضی» و فیلتر «منقضی‌شده» آن را نشان می‌دهند.
4. در پرونده مجوز، هشدار قرمز انقضا دیده می‌شود و دکمه‌های تأیید، فعال‌سازی، تعلیق و ازسرگیری حذف می‌شوند؛ فقط لغو یا مختومه‌سازی (در صورت داشتن نقش مجاز) باقی می‌ماند.
5. اگر همین مجوز در گزارش تحویل شیفت یا خلاصه ایمنی استفاده شود، به‌عنوان مجوز فعال شمرده نمی‌شود.

#### سناریوی ۷: جداسازی سازمان‌ها (Tenant Isolation)
1. با `demo_petro_supervisor` وارد شوید. فقط سازمان **پتروشیمی سپهر** و مجوز `PTW-202610-0201` را می‌بینید.
2. تلاش کنید آدرس یک مجوز فولاد را مستقیم باز کنید (مثلاً `/api/v1/permits/1/`)؛ پاسخ **404** است.
3. با `demo_viewer` وارد شوید و ببینید که فقط امکان مشاهده وجود دارد و دکمه‌های تغییر وضعیت نمایش داده نمی‌شوند.
4. تلاش کنید مجوز پتروشیمی را به تحویل شیفت سازمان دیگر متصل کنید یا سرپرست سازمان دیگر را انتخاب کنید؛ سرور درخواست را با خطای اعتبارسنجی رد می‌کند.

#### سناریوی ۸: تکرارپذیری و ایمنی بذرپاشی
1. یک‌بار `python manage.py seed_demo_data` را اجرا کنید و تعداد مجوزها/تحویل‌ها را یادداشت کنید.
2. رمز یکی از حساب‌های دمو را در رابط کاربری یا با ابزار مدیریتی تغییر دهید.
3. دوباره همان دستور را اجرا کنید. تعداد رکوردها تغییر نمی‌کند و رمز تغییرکرده **بازنویسی نمی‌شود**.
4. فقط در صورت نیاز آگاهانه: `python manage.py seed_demo_data --reset-demo-passwords` رمز حساب‌های دمو را به `Pass-12345-abc` برمی‌گرداند.
5. اگر از قبل سازمانی واقعی با کد `foolad-alborz` یا `sepehr-petro` و بدون نشانه‌های دمو وجود داشته باشد، دستور با پیام خطا متوقف می‌شود و آن سازمان را تغییر نمی‌دهد.

### ۴. رفع خطاهای متداول و بازگردانی امن محیط دمو

| نشانه | علت احتمالی | راه‌حل امن |
| :--- | :--- | :--- |
| «شما عضو فعال این سازمان نیستید» | حساب انتخابی در سازمان جاری عضویت فعال ندارد. | با حساب همان سازمان وارد شوید یا مدیر سازمان عضویت را فعال کند؛ مستقیماً داده عضویت را دستی تغییر ندهید. |
| خطای ۴۰۳/۴۰۴ روی مجوز یا تحویل شیفت | درخواست به سازمان دیگری اشاره دارد. | این رفتار امنیتی درست است؛ فقط داده‌های سازمان خود را باز کنید. |
| دکمه‌های تأیید/فعال‌سازی دیده نمی‌شوند | نقش کاربر، تفکیک وظایف یا وضعیت/انقضای مجوز اجازه نمی‌دهد. | با نقش مجاز وارد شوید؛ مجوز منقضی را ابتدا بررسی/لغو یا مختومه کنید. |
| تحویل شیفت قابل تأیید نیست | تحویل‌گیرنده تعیین‌شده شخص دیگری است یا نقش مجاز ندارد. | با همان تحویل‌گیرنده وارد شوید؛ برای تغییر، گزارش جدید با تحویل‌گیرنده واجد نقش ثبت کنید. |
| بذرپاشی با خطای سازمان/نام کاربری متوقف شد | کد سازمان یا نام کاربری دمو توسط داده واقعی اشغال شده است. | دستور را روی پایگاه داده دموی جداگانه اجرا کنید؛ نام یا کد واقعی را برای دورزدن محافظ تغییر ندهید. |
| فرانت‌اند به API وصل نمی‌شود | بک‌اند اجرا نشده یا آدرس API اشتباه است. | اجرای `python manage.py runserver 127.0.0.1:8000` و `npm run dev` را بررسی کنید؛ در صورت نیاز `VITE_API_BASE_URL` را تنظیم کنید. |

**بازگردانی امن دمو (فقط روی پایگاه داده اختصاصی دمو):**
1. سرورها را متوقف کنید.
2. از فایل پایگاه داده دمو یک نسخه پشتیبان بگیرید.
3. فقط اگر مطمئن هستید فایل متعلق به دمو است، آن را کنار بگذارید (حذف نکنید) و دوباره `migrate` و `seed_demo_data` را اجرا کنید.
4. هرگز فایل `db.sqlite3` واقعی را حذف یا بازنویسی نکنید و `seed_demo_data` را روی پایگاه داده مشترک اجرا نکنید.
5. برای بازگرداندن رمز حساب‌های دمو: `python manage.py seed_demo_data --reset-demo-passwords`.
