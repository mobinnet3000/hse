# AGENT.md — پروتکل دائمی توسعه مستقل و چندعاملی HSE Guard

این سند پروتکل اجرایی غیرقابل‌تغییر برای تمامی فازهای توسعه جاری و آتی سامانه HSE Guard است. کلیه عامل‌ها و مهندسان هوش مصنوعی موظف به رعایت دقیق بندهای این پروتکل در هر فاز می‌باشند.

---

## ۱. چرخه گام‌به‌گام هر فاز توسعه (Mandatory Phase Lifecycle)

هر فاز توسعه باید بدون استثنا شامل مراحل زیر باشد:
1. **بازرسی و ثبت خط مبنا (Inspection & Baseline):**
   - بررسی وضعیت Git و حفظ بدون تغییر کارهای کاربر (`git status`).
   - مطالعه گزارش فاز قبل (`docs/reports/`)، `docs/PROJECT.md`، `docs/TECHNICAL.md` و `README.md`.
   - اجرای آزمون‌های موجود و ثبت نتیجه دقیق عددی خط مبنا قبل از هرگونه تغییر کد.
2. **برنامه‌ریزی وابسته به وظایف (Task Breakdown & Ownership):**
   - ایجاد یا به‌روزرسانی سند برنامه فاز در `docs/plans/PHASE-XX.md`.
   - شکست فاز به وظایف مشخص با شناسه یکتا، مالکیت صریح، وابستگی‌ها، فایل‌های مجاز و ضوابط پذیرش.
3. **تفکیک مسئولیت و استفاده ایمن از زیرعامل‌ها (Subagent Delegation):**
   - در صورت پشتیبانی محیط از ابزار `invoke_subagent`، تفویض وظایف مستقل با تعیین دقیق فایل‌های مجاز به زیرعامل‌ها.
   - اجرای متوالی وظایف دارای وابستگی متقابل جهت پیشگیری از تداخل در مدل‌ها، مایگریشن‌ها یا روتینگ.
   - عامل اصلی همواره مسئولیت یکپارچگی، امنیت و اعتبارسنجی نهایی را بر عهده دارد.
4. **پیاده‌سازی برشی عمودی (Vertical Slice Implementation):**
   - پیاده‌سازی متوازن مدل داده، منطق تجاری سروری، API RESTful، ایزولاسیون چندمستأجری و رابط کاربری فارسی RTL.
5. **تولید داده‌های نمایشی معتبر و تکرارپذیر (Synthetic Demo Data):**
   - دستورات خط فرمان غیرمخرب و تکرارپذیر (مانند `python manage.py seed_demo_data`).
   - ایجاد داده‌های باکیفیت و منسجم بدون نقض داده‌های موجود و بدون جعل مراجع حقوقی.
6. **اعتبارسنجی کیفی چندلایه (Automated Quality Gates):**
   - آزمون‌های واحد و یکپارچگی بک‌اند، ارزیابی جداسازی سازمان‌ها و مجوزهای RBAC.
   - آزمون‌های کامپوننتی و گردش‌کار فرانت‌اند با Vitest و بیلد نهایی بدون خطای تایپ (`npm run build`).
   - بررسی‌های امنیتی (`check --deploy` و `npm audit`).
7. **راهنمای جامع نمایشی کاربر (User-Facing Demo Guide):**
   - تدوین راهنمای گام‌به‌گام برای کاربران غیرفنی در `docs/reports/PHASE-XX-DEMO-GUIDE.md`.
8. **گزارش مستند فاز (Verified Phase Report):**
   - ثبت گزارش رسمی فاز در `docs/reports/XX_phase_name.md` با ارائه شواهد اثبات‌شده.

## ۲. اصول غیرقابل‌مذاکره فنی و امنیتی

- **محدودیت پشته فناوری:**
  - بک‌اند: Django + Django REST Framework
  - فرانت‌اند: React 19 + TypeScript + Vite
  - پایگاه داده: SQLite (`db.sqlite3`) برای توسعه و MVP فعلی.
  - ممنوعیت مطلق: ورود یا ارجاع به Docker، Docker Compose یا Dockerfile.
- **ایزولاسیون چندمستأجری (Tenant Isolation):** هیچ کاربری تحت هیچ شرایطی نباید به رکوردهای سازمانی غیر از سازمان‌های مجاز خود دسترسی داشته باشد. کلیه QuerySetها باید در بک‌اند مقید به سازمان باشند.
- **حاکمیت اعتبارسنجی سروری:** عدم اعتماد به شناسه سازمان، وضعیت‌ها یا مقادیر ارسالی از کلاینت.
- **تضمین نظارت انسانی (Human-in-the-Loop):** خروجی‌های هوش مصنوعی صرفاً پیشنهادی بوده و پذیرش آن‌ها مستلزم تأیید صریح کارشناس ذی‌صلاح است.
- **ممنوعیت عملیات خودسرانه گیت:** هرگز بدون اجازه صریح کاربر کامیت، پوش یا دیپلوی انجام ندهید.
- **صداقت در گزارش‌دهی:** تفکیک شفاف میان قابلیت‌های پیاده‌سازی‌شده، تست‌شده، شبیه‌سازی‌شده و معوق. هرگز ادعایی بدون شواهد عددی ثبت نکنید.
